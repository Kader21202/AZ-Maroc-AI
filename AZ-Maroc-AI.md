# AZ-Maroc-AI

## Statut

Projet officiel de construction d’une plateforme numérique d’intelligence artificielle générique, cognitive, générative, spécialisée par domaine, modulaire et durable.

## Objectif

AZ-Maroc-AI n’est pas un simple chatbot.

La plateforme doit pouvoir :

- comprendre les demandes ;
- exploiter des connaissances vérifiables ;
- raisonner sur plusieurs types de problèmes ;
- générer des réponses structurées ;
- intégrer différents domaines spécialisés ;
- évoluer sans dépendre d’un seul modèle, fournisseur ou corpus.

## Décision fondatrice

AZ-Maroc-AI est construit à partir de zéro après l’expérience acquise avec :

- PPS-CognitiveAI-Core ;
- PPS-Maroc.ia-V2 ;
- PPS-AI-Workspace.

L’architecture générale déjà définie constitue l’hypothèse officielle de départ.

Elle ne doit pas être remise en cause sans preuve technique solide.

## Méthode de construction

Le projet avance selon le cycle suivant :

1. Un seul chantier.
2. Un seul objectif.
3. Un seul livrable.
4. Développement.
5. Tests.
6. Validation.
7. Commit Git.
8. Chantier suivant.

## Règles de travail

- Parler peu et produire des résultats concrets.
- Ne pas recommencer les discussions théoriques déjà terminées.
- Ne pas modifier l’architecture sur la base d’une simple idée.
- Étudier chaque composant avant de le développer.
- Inspecter les fichiers avant toute modification.
- Effectuer les opérations de développement depuis PowerShell.
- Tester chaque changement.
- Utiliser Git après chaque étape validée.
- Signaler clairement les faits, les hypothèses et les incertitudes.
- Utiliser la recherche comme support du développement, jamais comme moyen de repousser la construction.

## Étude préalable terminée

Le chantier RST-001 a étudié les architectures suivantes :

- chatbot ;
- RAG ;
- agents ;
- pipelines ;
- systèmes multi-agents ;
- ACT-R ;
- Soar ;
- Sigma ;
- plateformes modernes d’OpenAI, Anthropic, Google et Microsoft.

Cette étude est considérée comme suffisante pour commencer la construction.

## État actuel

La phase de réflexion générale est terminée.

La priorité est désormais la création progressive des composants réels d’AZ-Maroc-AI.

## Principe de continuité

Chaque nouvelle séance doit reprendre :

- le dernier chantier validé ;
- l’état réel du dépôt Git ;
- les décisions déjà prises ;
- le prochain livrable identifié.

Aucune séance ne doit repartir de zéro sans anomalie technique démontrée.
